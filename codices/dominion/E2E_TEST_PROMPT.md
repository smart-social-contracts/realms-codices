# Agent prompt: comprehensive E2E test of the Dominion codex

Read `codices/testing/E2E_AGENT_GUIDE.md` first — it defines the staging
environment, authentication, tooling, evidence, and the universal checks
U1–U6. Then execute this Dominion-specific journey with Playwright.

**Status caveat**: Dominion (v0.2.x) is the least curated codex. Unlike Agora
and Syntropia it declares **no `dependencies`**, **no `onboarding`
registration policy**, and **no seeded departments** — but it DOES declare a
codex-native currency (`DOM`, "Dominion Token", 8 decimals), fees, billing,
and a registration hook that invoices new users. Part of this test is gap
discovery: report every place where Dominion falls short of the platform
conventions the other two codices follow, as recommendations rather than
failures (unless something crashes).

Reference facts (assert against the currently published manifest — fetch it
from the file registry rather than trusting this list):

- Currency: `DOM` — this is the one codex where the wizard's Token step must
  be **pinned read-only** ("Set by the Dominion codex"), not a free choice.
- Fees: registration 1.00, monthly membership 0.50, proposal submission 0.10
  (in DOM).
- Governance: 7-day window, 20% quorum, 0.5 approval, proposal types
  `codex_change` and `treasury_spend`.
- Hook: `user_register_posthook` creates initial invoices for new users.
- Code files: `governance_automation.py`, `tax_collection.py`,
  `satoshi_transfer.py`.

## Journey

### D1 — Wizard (founder context)

1. Run U1. Additionally assert: the Token step shows the read-only
   codex-currency panel for **DOM** and does not let the creator pick another
   token. The Basics step's Member Registration remains a **user choice**
   (Dominion pins no registration policy) — record which default is offered.
2. Deploy a realm named `E2E-Dominion-<timestamp>`. Record canister ids.

### D2 — Founder experience

3. Run U2–U6. For U3, note: with no manifest dependencies, exactly the 9
   core extensions should be installed — anything more or less is a finding.
4. Verify the DOM token exists on the realm: Vault shows the DOM ledger /
   balance, and the token metadata (name "Dominion Token", 8 decimals)
   matches the manifest. If the deployment did NOT mint DOM (i.e. the
   codex-currency path is unimplemented end-to-end), this is a **blocking
   finding** — capture exactly what token the realm got instead.
5. Organizations/permissions: expect **no** seeded departments. Confirm the
   Organizations UI handles the empty state gracefully and that the founder
   can create a department manually (create one named `E2E-Test-Dept`,
   attach one permission, then delete it if deletion exists).

### D3 — Member onboarding & billing hook (second browser context)

6. Join the realm (use an invite generated by the founder if registration is
   closed, or open join otherwise — record which path applied).
7. Registration hook: the new user must receive an **initial invoice** in DOM
   (registration fee 1.00). Locate it (member dashboard, notifications, or
   `extension_sync_call` against the billing-related backend) and record the
   amount and validity. If no invoice is produced anywhere, blocking finding.
8. Membership activation requires `passport_verified` + `invoice_paid`:
   record whether/how the realm surfaces these requirements to the new user.

### D4 — Governance & codex code files

9. Voting: create a `treasury_spend` proposal as founder; verify window and
   quorum reflect the manifest; vote from the member context and record
   whether the vote is accepted or stage-gated.
10. Codex code files: check which of `governance_automation`,
    `tax_collection`, `satoshi_transfer` are actually reachable at runtime
    (e.g. codex_viewer listing, scheduled tasks, or backend queries). Not
    being wired up is an expected gap — document it precisely.

### D5 — Findings

Compile the report per the guide, with a dedicated **"Dominion gap list"**
section: missing dependencies declaration, missing registration policy,
missing org seeding, unwired code files, and any codex-currency plumbing
gaps — each with a one-line recommendation, so the list can seed the
Dominion curation issue.
